# 2026-08-24 Camera Alignment Debug Log

## Goal

Build a repeatable pipeline that pairs undistorted Real NoTag RGB images with
Unity NoTag RGB/depth renders for Depth-Anything training, without per-image
2D alignment.

## Final pipeline

1. Detect the 50 mm 5x5 ChArUco board in each Real Tag image.
2. Use the dataset's `capsule_intrinsics.npz` to solve the Real camera pose.
3. Convert the camera pose from the OpenCV tag frame to the Unity frame.
4. Render Unity Tag images first and verify the camera geometry.
5. When Tag alignment is acceptable, render NoTag RGB and depth with the same
   camera poses.
6. Undistort only the Real RGB image.
7. Rotate Unity RGB and depth by 180 degrees.
8. Pair Real RGB and Unity depth directly. Do not apply per-image
   `sx/sy`, `tx/ty`, rotation, pitch/yaw, homography, or other Tag-derived 2D
   warps.

## Findings

### Gate Fit, FOV, and lens shift

- Unity must use `Gate Fit = Horizontal`.
- `lensShift` controls the effective principal point and must be recalculated
  when the Real camera intrinsic calibration changes.
- Lens shift must not be inferred from a PnP translation offset.

For `trainingData20260818_2`, the final verified settings were:

```text
original = [-0.358725, -2.2282, 13.2305]
Horizontal FOV = 71.25 deg
lensShift = [0.164, -0.081]
```

The 46-image `A8E0_46x_trainingData` dataset uses a new intrinsic calibration:

```text
K =
[[758.938895,   0.000000, 723.126047],
 [  0.000000, 757.823668, 430.628780],
 [  0.000000,   0.000000,   1.000000]]

dist =
[-0.38518432, 0.14714940, -0.00389269, -0.00122705, -0.02813476]
```

The Unity capture was made with approximately:

```text
original = [-0.358725, -2.2282, 13.2305]
Horizontal FOV = 70.92 deg
lensShift = [0.170, -0.117]
```

### The apparent 15 mm translation

The earlier `Unity20280818_2_6` analysis reported an approximately -15 mm X
translation. Moving the Unity Tag back to its correct X position removed this
offset. It was a Tag placement/frame mismatch, not a camera correction that
should be applied to NoTag renders.

After correcting Tag X, original Z, FOV, and lens shift,
`Unity20280818_2_8_tag` reached:

- Direct Tag corner RMSE: 1.60-2.88 px.
- Mean position difference: `[+0.043, +0.077, +0.259] mm`.
- Mean rigid translation: `[-0.020, +0.012, +0.177] mm`.

### 46-image dataset validation

`A8E0_46x_trainingData/trainingData/Unity20280824_1_tag` was compared against
all 46 Real Tag images using the new NPZ:

- Mean direct Tag corner RMSE: 3.04 px.
- Median direct Tag corner RMSE: 2.96 px.
- Maximum direct Tag corner RMSE: 5.45 px.
- 39/46 images were below 4 px.
- Mean position difference: approximately
  `[-0.085, -0.053, +0.537] mm`.

This is sufficient to use the NoTag renders without a 2D warp.

## Depth-Anything package layout

`build_depth_anything_training_pairs.py` writes:

```text
Depth_anything_training/
  real_rgb_raw/   # original Real NoTag RGB
  real_rgb/       # Real RGB undistorted with the dataset NPZ
  unity_rgb/      # Unity NoTag RGB rotated 180 degrees
  unity_depth/    # matching Unity depth rotated 180 degrees
  preview/        # Real | Unity | blend | depth preview
  manifest.csv
  metadata.json
  README.md
```

The current Unity depth PNG is an 8-bit grayscale shader output. It must not be
treated as metric depth until the shader's near/far range and encoding formula
are confirmed.

## Main scripts

- `analyze_tag_camera_correction.py`: physical camera/intrinsic and PnP
  comparison with leave-one-out validation.
- `rebuild_tag_id_compare.py`: visual Tag/NoTag comparison panels; supports
  NoTag comparison without Tag warp.
- `regen_unity_cam2tag_face.py`: converts Real tag-frame poses to Unity camera
  poses and supports a configurable Unity `original`.
- `trainingData20260818_2/rerun_mode5_poses.py`: recomputes offline Mode 5
  poses using a selected dataset directory and its NPZ.
- `build_depth_anything_training_pairs.py`: creates consistently named
  Real-RGB/Unity-RGB/Unity-depth triplets.
- `gen_unity_pose_grid.py`: generates Unity-readable pose grids while retaining
  a selected source orientation.
- `decode_unity_depth8_to_metric.py`: optional 8-bit depth decoding utility;
  use only after confirming the shader encoding range.

## Important rule

Every new Real dataset must use its own `capsule_intrinsics.npz` to recompute
Tag PnP poses before generating the Unity camera CSV. Reusing an older
`camera_pose_relative_to_tag.csv` without checking its calibration can produce
incorrect Unity coordinates.
